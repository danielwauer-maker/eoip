# SQL Raw & Staging Layer

## Purpose

EOIP uses PostgreSQL 16 as its reproducible relational analytics foundation.

The SQL layer is deliberately split into:

```text
Generated ERP source data
        ↓
      raw
        ↓
      stg
        ↓
Dimensional model (EOIP-05)
```

EOIP-04 owns only the first two database layers.

## Raw schema

The `raw` schema mirrors the operational source entities generated by EOIP-03.

Characteristics:

- 19 source tables
- source grain preserved
- typed columns
- primary keys
- relevant foreign keys
- source-oriented naming
- no star-schema dimensions or facts
- no dashboard KPI materialization

The loader inserts data in dependency order so relational constraints remain active rather than being disabled for convenience.

## Staging schema

The `stg` schema normalizes source semantics for later dimensional modeling.

Key views include:

- `stg.customer`
- `stg.product`
- `stg.sales_order_line`
- `stg.sales_document_line`
- `stg.inventory_movement`
- `stg.value_movement`
- `stg.inventory_balance`
- `stg.purchase_receipt_line`
- `stg.warehouse_transfer_line`

### Sales sign convention

`stg.sales_document_line` combines posted invoices and credit memos.

Invoices:

- quantity: positive
- gross sales: positive
- discount: positive
- net sales: positive

Credit memos:

- quantity: negative
- gross sales: negative
- discount: negative
- net sales: negative

This lets later models aggregate net sales without maintaining separate return arithmetic in every downstream query.

## Inventory and value separation

`stg.inventory_movement` preserves physical quantity movement.

`stg.value_movement` preserves actual cost and sales-value movement and exposes product/warehouse context through the linked inventory ledger entry.

The dimensional model can therefore derive gross profit with traceable source lineage rather than relying on a generated gross-profit field.

## Local database

Start PostgreSQL:

```bash
docker compose up -d postgres
```

Generate data:

```bash
eoip generate \
  --company-profile ../enterprise-data-ai-portfolio/data/companies/nordwerk.yaml \
  --output data/generated
```

Load the database:

```bash
eoip load-db \
  --database-url postgresql://eoip:eoip_local@localhost:5432/eoip \
  --input data/generated
```

The command:

1. applies versioned SQL migrations,
2. truncates the raw layer,
3. loads all 19 source entities,
4. runs database reconciliation,
5. writes `database-validation.json`.

## CI quality gate

GitHub Actions starts PostgreSQL 16 and runs the complete pytest suite.

The integration test proves:

- migrations apply cleanly,
- every raw table receives the expected row count,
- staging sales counts reconcile,
- credit memo signs are normalized,
- transfers reconcile,
- invoice totals reconcile,
- value entries map one-to-one to inventory ledger entries,
- inventory balance reconciles to quantity movement,
- the entire load is repeatable.
